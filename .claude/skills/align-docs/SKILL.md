# align-docs：文件與程式註解對齊現況

想法常常轉向，文件與程式註解會留下**落差**：歷史留在現況裡、事實變了沒跟著改、規劃寫得像已經做好。這份是全面掃一次的做法。「現行文件只寫現況、歷史寫進時間線」的規則在 [CLAUDE.md](../../../CLAUDE.md) 的協作方式；這裡把同一條規則也套到程式註解。

只改工作區。作者說 commit 或開 PR 時照 [ship](../ship/SKILL.md) 送出，commit 訊息與 PR 標題含「對齊現況」，下次第 1 步才找得到起點。

## 1. 定範圍

```sh
git status --short
git log --oneline --grep "對齊現況" -1        # 上次對齊的 commit
git log --stat <上次對齊>..HEAD                # 之後改過哪些地方
```

- 從 [ADR 索引](../../../docs/adr/README.md)的「已取代」與[時間線](../../../docs/history/timeline.md)，列出被放棄的做法用過的名詞（例如像素、`rig.json`、Python、SwiftUI 版），當成第 2、3 步的搜尋字。

完成：知道上次對齊之後改過哪些區域；手上有一份被放棄做法的名詞。

## 2. 程式註解

```sh
cd ios && grep -rn -E '以前|原本|改成|改為|不再|舊|當時|修過|暫時|目前|之後會|還沒|<被放棄做法的名詞>' \
  --include='*.swift' --include='*.metal' PenguinFamily PenguinFamilyTests
```

- 每個命中歸成三類：**現況**（例如「維持原本的方向」這種正常用法，留著）、**歷史**（照第 4 步處理）、**錯誤**（和程式不符，改正）。
- 第 1 步列出的區域裡，每個檔案的開頭註解整段讀，逐句對照程式：數字、型別與函式名稱、流程。

完成：每個命中都歸了類；改過區域的每個檔案開頭註解都對照過程式。

## 3. 現行文件

範圍是 CLAUDE.md 文件地圖裡的現行文件，加上 [GLOSSARY.md](../../../GLOSSARY.md)；`docs/history/` 是歷史，不在範圍內。

- [架構](../../../docs/architecture.md)與[程式地圖](../../../docs/code-map.md)整份讀：目錄圖、模組邊界、流程圖、對照表都要和程式一致，還沒建立的標「未建立」。
- 其他文件：用第 2 步的搜尋字掃，再讀和第 1 步改過區域相關的段落。
- TASKS：進度段落、「等你決定」「現在輪到你」是否仍成立。
- 遊戲設計：「要新畫的美術」只留還沒畫的。
- 詞彙表：程式與文件新出現的領域用語補進去。

完成：架構與程式地圖每一段都對照過程式；其他每份現行文件都掃過，相關段落讀過。

## 4. 怎麼改

| 東西 | 處理 |
|---|---|
| 現行文件、程式註解裡的歷史 | 改寫成現況；決定的理由與「作者某日決定」留著 |
| 錯的事實 | 改正，並記進時間線 |
| 規劃寫得像已經有 | 標「未建立」，或改寫成計畫 |
| 時間線、`docs/history/` | 只在後面新增 |
| ADR 本文 | 保留原文；過時的條目只補「（日期：由 ADR XXXX 取代）」標註，補之前先用 AskUserQuestion 問作者 |
| 有查證日期的調查 | 本文是當時的紀錄，保留；只改開頭說明裡現在不成立的句子 |
| TASKS 已勾選的項目 | 保留原文（項次到處被引用，描述是做過什麼的紀錄） |

拿掉一句歷史之前，先在時間線搜得到它；搜不到就補進它發生的那一天。

完成：表裡每一種都照做；每一句拿掉的歷史都在時間線找得到。

## 5. 時間線與檢查

- 時間線今天的日期下加一筆：拿掉了哪些說法、各自記在哪一天、順便改正了什麼。
- `git diff --word-diff` 逐段看：句子留在原本的段落、連結的錨點存在。
- `ios/` 只改註解：`git diff -- ios | grep '^[-+][^-+]'` 的每一行，變的都只有註解。

完成：時間線有這一筆；差異逐段看過；`ios/` 的程式沒有變。

## 6. 回報

用繁體中文列出：程式註解與文件各改了什麼（錯的事實另外標出）、刻意沒動的、要作者決定的事。

查角色包時只看檔名與欄位，資料夾名稱寫成 `<角色>`：角色 id 可能帶角色名稱，不出現在輸出與回報裡。
