# 路線圖

工時都是 2026-11-04 的粗估。每個階段都由作者親自試用後，決定是否進下一階段。

路線分成兩條，共用角色聖經與事件紀錄：

- **路線一：箱庭生活**：App 不接 AI 也能完整運作，預寫台詞全由作者撰寫。
- **路線二：聊天靈魂**：主人用自己的話和企鵝聊天，App 才開始接 AI。

目前進度、待辦與待作者決定的事項見 [TASKS.md](../../TASKS.md)。

## 待驗證

這些都還沒有實測，不可當成已知事實：

- RealityKit 是否足以做這款遊戲（S2）
- AI 生成 3D 對絨毛玩偶的效果，以及縮小後是否認得出來（S1）
- 遠景的小角色能否表現出個性（A1）
- 規則式隨機事件能否帶來「活著」的感覺，不靠即時 AI 是否足夠（A1）
- 作者自寫的台詞量是否足以避免重複（A1）
- 不含聊天的親友測試適用哪些法規與 Apple 規定（A2 前核對）
- 各模型的繁中人設演出品質（B1 盲測）
- 支援的最低 iOS 版本（S2）
- 上實機需要哪種 Apple 帳號與簽署方式（S2 開始前查證）

# 路線一：箱庭生活

## A0：技術驗證（約 3 天）

**S1 素材實驗（1 天）**
1. 查 Meshy、Tripo 的現行條款（第三方資料對免費方案授權說法不一），並確認生成的模型會不會公開。向作者確認後才上傳照片。
2. 用作者自己拍的照片生成兩隻的 3D 模型，匯出 USDZ。
3. 放到 iPhone 上看遠景與近景。

- **通過**：遠景一眼認得出是自己的玩偶，近景不出戲。
- **未通過**：改用多角度實拍去背的紙片 2.5D，並和作者重新檢視 [ADR 0001](../adr/0001-realitykit-swiftui.md)，因為它的前提是走真 3D。
- **無論結果**：都把素材路線寫成 ADR。

**S2 RealityKit 驗證（2 天）**
1. 在 SwiftUI 內以 RealityView 建立非 AR 場景與固定鏡頭。
2. 兩隻企鵝用程式做搖擺走路，點擊有反應。
3. 長按時鏡頭拉近，並有 Core Haptics 觸覺回饋。
4. 確認最低 iOS 版本。

- **通過**：實機順暢，抱抱手感讓作者想再按一次。把 [ADR 0001](../adr/0001-realitykit-swiftui.md) 改為 accepted。
- **未通過**：回報卡點，由作者決定是否改用 Unity。

## A1：可每天打開的雛型（約 2～3 週）

- **箱庭**：一個小場景，簡單的日夜或時間變化。
- **行為系統**：閒晃、打瞌睡、跌倒、看向對方、一起行動。
- **隨機事件**：依條件、權重與冷卻時間發生，事件可以留下共同回憶。
- **事件與台詞清單**：列出每個事件需要的台詞，由作者撰寫。
- **互動**：點一下、拖曳引導、長按抱抱。
- **鬥嘴**：用對話泡泡呈現預寫台詞，依時間、狀態和兩隻的組合選句。
- **難過時的陪伴**：靠抱抱或主人主動選心情進入難過模式，不需要 AI。
- **關係養成**：記住相處與共同回憶，解鎖新行為。互動次數只在內部當解鎖條件，不顯示成數值。
- **事件紀錄**：先記下箱庭發生的事，路線二才能接上。

**驗收**：作者連續使用一週，記錄哪些時刻覺得「這就是牠」。

## A2：親友測試（不含聊天，約 1 週）

- **發送前**：玩偶是市售品，由作者決定改為原創造型、取得授權，或在了解風險後維持原樣（見 [ADR 0004](../adr/0004-plush-likeness-private-use.md)），並核對不含聊天的版本適用哪些規定。
- **TestFlight**：需 Apple Developer Program 會員，參與者依[安全與隱私底線](../../.claude/rules/safety-privacy.md)。
- **回饋重點**：親友是否覺得牠們可愛、會不會想再打開。

## A3：小工具與步數（約 2 週）

- **主畫面小工具**：顯示兩隻企鵝當下的狀態。
- **步數連動**：用 Core Motion 或 HealthKit 取得步數，轉成箱庭事件或獎勵。拒絕權限也不影響主要玩法。

## A4：地圖連動（需另外規劃）

定位連動的權限、隱私和背景耗電都比步數重，等步數玩法驗證有效後再設計。

作者在選核心體驗時勾選了走路／地圖連動，分階段是規劃建議；作者想提前的話可以調整。

# 路線二：聊天靈魂

A2 之後，由作者決定先做 A3 還是 B1。

## B1：聊天（約 2 週）

- **模型盲測**：用角色聖經測試繁中演出，先比較 Haiku 5.5、Sonnet 5.5、Opus 5.5。供應商與模型由作者決定；目前還沒比較其他供應商，作者想比較時再加入。
- **薄後端**：保管 API 金鑰、限流、設費用上限。語言和託管方式到此階段再選。
- **聊天與記憶**：依 [ADR 0002](../adr/0002-hybrid-soul-engine.md)、[ADR 0003](../adr/0003-on-device-memory.md) 實作。
- **與箱庭連接**：聊天能提到事件紀錄裡剛發生的事，聊天內容也能影響企鵝在箱庭的狀態。
- **難過模式**：在主人主動表達之外，加上從文字判斷情緒，並定義何時進入與離開。
- **危機情境測試清單**：撰寫清單，並查證適用的真人求助資源（目前都還沒有）。
- **安全**：實作[安全與隱私底線](../../.claude/rules/safety-privacy.md)的全部項目。

**驗收**：作者用 AI 聊一週，再加上危機情境測試清單全部通過，並確認後端沒有留下聊天內容。

## B2：開放聊天給親友（約 1 週）

- **開放前**：依[安全與隱私底線](../../.claude/rules/safety-privacy.md)完成測試對象檢查。
- **回饋重點**：親友是否覺得聊天的企鵝和箱庭裡的是同一隻，費用是否符合預期。

## 假設性擴充（尚未決定）

App 執行時用 AI 做聊天以外的事，例如企鵝主動提起主人昨天說的話，或把當天事件寫成日記。
