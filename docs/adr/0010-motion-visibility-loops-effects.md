# 動作片段可以換部件、可以循環，特效是不分物種的共用形狀（擴充 ADR 0009）

## 背景

A1 第 13 項的打瞌睡，作者 2026-11-23 看過私有素材 repo 的原型後定案（玩法見[遊戲設計的睏意](../product/game-design.md#睏意打瞌睡與睡覺)，調查見 [doze-and-sleep](../research/doze-and-sleep.md)）：

- 原地坐下，閉眼點頭，嘴邊的鼻涕泡泡跟著呼吸變大變小，頭上飄 Z，沒人點時一直循環。
- 被點時轉向鏡頭，泡泡破掉，從坐姿彈起來、眼睛變圓，用一隻手揉眼睛。

照 [ADR 0009](0009-characters-species-motion-data.md)，片段只能轉動、縮放、移動部件，App 做不出這些：

| 需要 | 現在 |
|---|---|
| 閉眼、圓眼：換形狀 | 眼睛畫在頭的部件裡，沒辦法換 |
| 坐著時腳伸到身體前面；揉眼睛時手在臉前面 | 每個部件畫的先後固定；外框是整隻先描一次，畫在別的部件前面的部件會沒有外框 |
| 打瞌睡一直循環，直到被點或自己醒 | 一次性的動作播完就停在最後一格，只有步態會循環 |
| Z 與泡泡淡入淡出、泡泡破掉 | 繪製清單只有多邊形與角色，沒有特效，也沒有透明度 |

## 決定

### 部件可以藏起來，片段決定什麼時候換

做法和 Spine 的插槽相同：同一個位置準備好幾個部件，片段決定這一刻顯示哪一個。

- **造型**：部件可以寫 `hidden: true`，平常藏起來，例如閉眼、圓眼、伸到前面的腳、在臉前面的手。
- **片段**：除了每個部件的軌道，多一組 `visible`，寫法是 `{ 部件: [[秒, 1 或 0], ...] }`。從那一秒起顯示或藏起來，不內插。
- **藏起來的部件**：外框和顏色都不畫。畫面準備直接不放進繪製清單，繪圖不用改。

### 部件可以不描共用的外框

- **`silhouette` 可以是空的**：那個部件不參加「整隻先描一次」的外框，例如眼睛。
- **畫在別的部件前面的部件**：在自己的顏色層加一層外框色的描線，例如伸到前面的腳、在臉前面的手。這不用改格式，只是資料。

### 一次性的動作可以循環

- **動作可以寫 `cycle`**：寫了就是循環的動作，例如打瞌睡。
- **播放**：照 `cycle` 接回開頭，和步態相同。
- **模擬**：循環的動作不會「播完」，要由狀態機換成下一個動作。坐下、自己醒來、驚醒揉眼睛還是一次性的動作。

### 特效：形狀共用，怎麼動照樣是片段

- **形狀**：Z、泡泡、泡泡破掉的線放在公開 repo 的 `Resources/effects.json`。它們不是玩偶的造型，不受 [ADR 0004](0004-plush-likeness-private-use.md) 限制，所有物種共用。格式和造型的部件相同（轉軸、顏色層），不描共用外框。App 載入時畫成貼圖。
- **怎麼動**：照樣在私有素材 repo 用算式算，匯出成片段。片段多一組 `effects`，每個特效一條軌道，每格多一個透明度：`[秒, 旋轉, 橫向縮放, 縱向縮放, 位移 x, 位移 y, 透明度]`。
- **位置**：位移照這隻角色畫布的座標，所以泡泡黏在嘴邊、Z 從頭頂冒出來，都是每隻自己的資料。App 不分物種，也不放特效的算式。
- **翻轉的方向**：只翻位置，形狀不翻，所以 Z 不會變成反的。
- **畫的先後**：特效畫在那隻角色後面一點，也就是蓋在角色上面。繪製清單多一種項目：特效（形狀、矩陣、透明度），繪圖多支援透明度。

### 格式的版本

- **`motion.json` 升到第 3 版**：多了 `visible`、`effects` 與動作的 `cycle`。第 2 版照樣讀得懂，當作沒有換部件、沒有特效。
- **`vector.json`**：多了可以不寫的 `hidden`，`silhouette` 可以是空的。版本不變。

## 代價

- **部件變多**：
  - 正面與左前的眼睛要從頭拆出來（睜眼、閉眼、圓眼）。
  - 正面的腳要從身體拆出來，再加一份畫在前面的。
  - 正面多一隻畫在臉前面的手。
  - 兩隻都要改，私有素材 repo 的造型、匯出與對照檔一起改。

  這些部件都很小，貼圖照部件的範圍準備，但加起來不少：2026-11-23 在 3 倍螢幕的模擬器量，兩隻的貼圖從 25,706KB 變成 31,610KB（含共用特效）。照這樣估，名單到第三、四隻就會碰到 50MB 的門檻（ADR 0009 估的是第四隻左右），記憶體預算的測試會擋下來。
- **一份部件、兩份位置**：伸到前面的腳和平常的腳是兩個部件，形狀改一份時要記得另一份。在私有素材 repo 用同一個形狀產生兩份，就不會不一致。
- **特效的軌道**：Z 輪流放在固定幾條軌道上（打瞌睡 9 秒一個循環冒 8 個，放在 4 條），Z 的間隔要能整除循環才接得上。
- **檔案變大**：`motion.json` 從一隻 210～270KB 變成約 1MB（第一隻 1,068KB、第二隻 967KB，2026-11-23）。打瞌睡的循環動得慢，先照每秒 20 個關鍵影格取，誤差超過 0.1 單位的地方一樣再加密（照每秒 60 格時約 2MB）。整段都藏著的部件不匯出軌道。讀檔在載入畫面期間做。測試用的對照檔一隻約 5～6MB，不進 git。
- **打瞌睡時一直畫**：循環的動作不會播完，模擬一直跑節拍、遊戲迴圈也一直畫（和走路一樣）。
- **私有素材 repo 的預覽要讀公開 repo 的特效形狀**：瀏覽器打開本機檔案時不能直接讀別的資料夾的 JSON，實作時再處理，例如匯出時順便產生一份給預覽用的 JS。
- **不做的**：
  - 片段之間的骨架父子關係（例如眼睛自動跟著頭）：眼睛的軌道由匯出照頭的動作寫一份，App 保持只照軌道播。
  - 畫的先後跟著片段變（Spine 的 draw order 軌道）：用藏起來的第二份部件代替。

## 定案

提案時的條件：

- 測試全過，含換部件、循環的動作與特效從角色包讀進來，一直到繪製清單；假鯊魚照樣能跑。
- 作者在 iPhone 上看過兩隻坐著打瞌睡、被點驚醒揉眼睛，和原型一樣。

2026-11-23 實作完成（v0.0.10）：222 個測試全過，兩隻的新動作和 `vector.js` 的算式逐格比對都相同；模擬器上看過兩隻坐著打瞌睡（閉眼、泡泡、Z）。同一天作者在 iPhone 上看過，通過，定案。
